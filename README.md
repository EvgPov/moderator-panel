# «Панель модератора»

Это задание не обязательно для выполнения. Если вы хотите закрепить 2 прошедшие темы и заработать дополнительный бонус(ооочень хороший бонус) к сдаче своих работ в этом семестре, то это стоит вашего внимания)

Вы получаете почти готовое приложение — внутреннюю панель модератора блог-платформы. Часть компонентов не дописана, а одна страница работает, но заметно тормозит. Ваша задача — довести приложение до рабочего состояния и устранить проблемы производительности.

Данные приходят с тестового API [jsonplaceholder.typicode.com](https://jsonplaceholder.typicode.com): посты, комментарии, авторы и 5000 записей медиатеки.

## Запуск

```bash
npm install
npm run dev
```

Перед сдачей проверьте, что проект собирается без ошибок:

```bash
npm run build
```
## Структура

```
src/

  hooks/                    useFetch, useDebounce, useMutation
  components/               общие компоненты
  pages/                    страницы приложения
  utils/                    вспомогательные функции
  types.ts                  типы данных API
```

## Рекомендуемый порядок

Сначала задачи 1 и 2 — без них не заработает ни одна страница, включая готовые. Затем 3–5, и только потом оптимизация (6–7).

## Часть 1. Работа с API

### Задача 1. Хук `useFetch`

Файл: `hooks/useFetch.ts`.

- Запрос уходит при монтировании и при каждой смене `url`.
- Хук возвращает `data`, `isLoading`, `error`, `status` и `refetch`.
- Ответ со статусом 4xx/5xx считается ошибкой.
- В `status` записывается HTTP-статус ответа.
- Предыдущий запрос отменяется через `AbortController` — при смене `url` и при размонтировании.
- `AbortError` не показывается пользователю.
- `refetch()` повторяет запрос по тому же адресу.

Проверка: страница «Авторы» загружается и показывает таблицу.

### Задача 2. Хук `useDebounce`

Файл: `hooks/useDebounce.ts`.

Хук возвращает значение, которое обновляется только после того, как исходное не менялось `delay` миллисекунд.

### Задача 3. Список постов

Файл: `pages/PostsPage.tsx`.

- Поиск с задержкой 500 мс: запрос не должен уходить на каждую букву.
- Пагинация по 10 постов.
- При новом поиске пользователь возвращается на первую страницу.
- Состояния: «Печатаете...», загрузка, ошибка с кнопкой «Повторить», «Ничего не найдено».
- Кнопки пагинации заблокированы во время загрузки. «Вперёд» заблокирована, если следующей страницы нет.

Проверка: откройте вкладку Network и быстро наберите слово в поиске — должен уйти один запрос, а не по запросу на каждую букву.

### Задача 4. Страница поста

Файл: `pages/PostPage.tsx`.

- Загрузите пост и его комментарии.
- Под заголовком выведите автора: `<AuthorBadge userId={post.userId} />`.
- Если пост не найден (статус 404), покажите «Пост не найден» и ссылку на список. Проверьте на адресе `/posts/9999`.
- Любую другую ошибку покажите через `ErrorMessage` с кнопкой «Повторить».
- У комментариев свои состояния загрузки и ошибки: если они не загрузились, пост всё равно должен отображаться.

### Задача 5. Форма комментария

Файл: `components/CommentForm.tsx`.

- Отправка через `useMutation` (POST на `endpoints.comments`).
- Во время отправки кнопка заблокирована и показывает «Отправка...».
- После успешной отправки новый комментарий появляется в списке на странице поста, а поля формы очищаются.
- При ошибке поля не очищаются, под формой видно сообщение об ошибке.

jsonplaceholder не сохраняет данные: после перезагрузки страницы ваш комментарий исчезнет — это нормально.

## Часть 2. Оптимизация

### Задача 6. Медиатека

Файл: `pages/PhotosPage.tsx`.

Страница загружает 5000 записей и работает, но интерфейс подтормаживает: поиск реагирует с задержкой, кнопки «В избранное» срабатывают не сразу, а страница лагает даже тогда, когда вы ничего не делаете.

На странице не менее пяти проблем производительности. Найдите и исправьте их.

Ограничения:

- логику и внешний вид страницы не меняйте;
- вызов `simulateHeavyRender()` не удаляйте — он имитирует дорогой рендер строки;
- для виртуализации используйте уже установленный `@tanstack/react-virtual`.

Перед правками запишите профиль в React DevTools (вкладка Profiler) и включите подсветку рендеров. После правок сравните результат.

### Задача 7. Разделение кода

Файл: `App.tsx`.

Сейчас код всех страниц попадает в один бандл. Сделайте так, чтобы код каждой страницы загружался только при переходе на неё. Пока код страницы грузится, пользователь должен видеть индикатор загрузки. Шапка с навигацией при этом не должна пропадать.

Проверка: после `npm run build` в папке `dist/assets` появляются отдельные файлы для страниц.

## Критерии приёмки

| Блок | Что проверяем |
|---|---|
| `useFetch` | Отмена запросов, обработка 4xx/5xx, `status`, рабочий `refetch` |
| `useDebounce` | Один запрос после окончания ввода, таймер очищается |
| Список постов | Поиск, пагинация, сброс страницы, все четыре состояния |
| Страница поста | 404 отличается от других ошибок, автор, комментарии, повтор запроса |
| Форма | Блокировка при отправке, очистка после успеха, вывод ошибки |
| Медиатека | Исправлено не менее пяти проблем, каждое исправление обосновано |
| Разделение кода | Страницы в отдельных чанках, шапка не пропадает при загрузке |
| Код | Нет запросов внутри компонентов в обход хуков, нет `any` |
